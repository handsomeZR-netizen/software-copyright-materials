# 用户交付布局

用户希望代码集中保管、当前材料便于查找。最终项目根目录优先只留下：

- code.zip：全部原创源码、必要运行资源（含可直接运行所需dist）、测试、配置、锁文件、启停脚本、构建/启动说明、第三方许可和逐文件校验。ZIP内相对目录结构完整；排除node_modules、缓存、运行日志及无关历史材料。依赖可按锁文件重新安装。
- 软件材料包/：根部放当前使用说明书PDF、源程序鉴别PDF及已有申请信息填写清单.md。子目录可编辑原稿放manual-tex/main.tex、实际配图、source-tex/main.tex及字体许可；源码映射放收录清单、真实行号、统计与哈希。

规范、旧模板、核验报告、运行证据、历史DOCX和旧PDF、制作脚本、skill备份保存在独立归档目录，不在当前材料包根部散放。用户不需要再次获取填写Markdown时，更新原文件但不重新全文推送。

整理顺序：盘点→生成代码ZIP及清单→从ZIP核验每文件哈希→保管运行证据与不再显示的文件→整理当前材料→核对最终布局及两类PDF→归档重打包。历史资料有价值时移入归档，不在材料包累积版本。删除或移动散放文件前，先验证已有可恢复副本；Windows递归操作用原生LiteralPath，并核验绝对路径在用户指定项目范围内。清理缓存时保留可能含独有数据的文件。

后续改源码需先解压code.zip到临时工作区；修改完成后重建、核验并更新ZIP。修改说明书可直接编辑软件材料包/可编辑原稿中的同一TeX源；若准备脚本在ZIP中，先解压。不要重新展开完整工程污染用户工作目录。
