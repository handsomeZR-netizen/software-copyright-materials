# 合作开发协议模板使用

## 何时制作

合作开发协议默认不制作。只有用户点名要协议（或明确说明是合作开发并要求准备权属证明）时才生成；独立开发、单位开发等情形不附带协议。

## 模板与脚本

默认模板：../assets/agreement-template/合作开发协议模板.docx。模板来自用户选定的开发协议DOCX，保留原条款、页眉页脚、字体、段落和签署表格，已清除原项目人员、名称、日期。它是协议的内容与格式依据；不要另起TeX协议、重新设计版式或任意增删条款。模板中的XXX只是脚本替换位，不得出现在交付件中。

用 ../scripts/agreement.py 生成，不手工逐段改：

```
python /绝对路径/scripts/agreement.py --config /项目/软著材料准备包/agreement.json --pdf
```

agreement.json 与 config.json 放在同一目录，字段：software_name、software_version、development_date、signing_date、purpose（一句“本软件用于……。”，取自开发目的字段）、parties（按署名顺序列出 name、id_number、duties）、handler（缺省为合作方一）、output（建议“合作开发协议/合作开发协议.docx”）。脚本支持2–4方，自动删除多余合作方段落、调整“一式N份”和签署栏，校验身份证校验位与签署日期，残留XXX时报错。--pdf 调用本机Word导出并刷新页码域；Word不可用时用其他DOCX渲染工具导出。

## 填写规则

1. **著作权归属**：统一写为协议各方共同享有软件著作权，不设份额、百分比或按比例分配收益；商业使用、许可、转让和收益分配写为由协议各方共同协商并书面确定。保留其他财产权许可、保密、违约和争议解决条款。
2. **称谓**：沿用模板的“合作方一/合作方二……”。法律上不要求写“甲方/乙方”，登记审查关注的是协议双方姓名、身份信息与申请表著作权人一致、署名顺序一致及签字齐全。用户明确要求甲乙方时再改称谓，正文与签署栏同步。
3. **协议签署日期**：必须早于开发完成日期。登记办法未明文规定，但审查实务中协议日期等于或晚于开发完成日期会被要求补正（见sources.md）。用户未给日期时，取开发完成日期前约三个月内一个合理的工作日写入，并在回复中告诉用户所取日期，提醒双方签字时认可该日期；不要写成与开发完成日期同一天。
4. **登记申请经办人**：默认合作方一（第一著作权人），正文“一、软件基本信息”和“六、登记办理与材料配合”两处一致。用户另行指定时以其为准。
5. **各方分工**：用户未提供时，依据项目实际代码结构（服务端/前端/算法模块/测试与文档）为每方写一句合理分工，只写软件中真实存在的模块；合作方一通常兼顾总体设计和登记材料整理。分工段后不保留“具体分工可由协议各方根据项目进度进行补充或调整……”之类的说明句。
6. **不留红色XXX**：交付件不得出现XXX占位。签署栏日期留空成“    年  月  日”供手写；其他用户确实未定的事项同样留空白，并在回复和填写清单中列出。
7. **身份信息**：用户提供身份证号时写在“协议各方”段并做校验位检查；同时写入申请信息填写清单的著作权人信息表。

## 交付与检查

协议放在 output_dir/合作开发协议/ 下（DOCX＋PDF），与 package 生成的交付目录分开，避免被重建覆盖；申请信息填写清单的上传材料表加“权属证明（合作开发）”一行，并把开发方式、权利取得方式和著作权人信息同步更新。著作权人确定后同步修改 config.json 的 copyright_owner 与说明书 TeX 的 \copyrightOwner，再 build/verify/package。

导出后逐页检查：章节标题不孤行、签署表格不跨页、姓名与签署空间完整、页码为“第 N / M 页”，全文无XXX。导出前确认目标DOCX没有在Word中打开（被占用时保存会失败），不要关闭用户已打开的Word窗口。

模板和最终协议分开保存。对外同步模板时保留匿名占位，检查正文、表格、页眉页脚、批注、修订和文档元数据，排除原项目个人信息。不要把模板条款当作各方已签署的事实。
